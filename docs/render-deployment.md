# Render Deployment

CollabSpace deploys to Render as a Blueprint. The configuration at the repository root creates:

- One Docker-based web service that serves the built React frontend and API from the same origin, applying Prisma migrations before starting.
- A GitHub webhook background worker.
- Private, persistent Render Postgres and Key Value instances.

## Create the Render services

1. Push the repository, including `render.yaml`, to GitHub.
2. In Render, choose **New → Blueprint**, connect `piyusshhjangid/CollabSpace`, and select the branch to deploy.
3. Review the service list and current plan prices in Render before confirming. The configured always-on plans are approximately **$30 USD/month**: $7 API, $7 worker, $6 Postgres, and $10 Key Value. The static site has no compute charge. Usage, bandwidth, and future plan changes can affect the total.
4. After Render finishes deploying, open `collabspace-app` and use its `onrender.com` URL for the app and API.

The app service references its own Render URL for Socket.IO CORS and invitation links. `JWT_SECRET` and `GITHUB_WEBHOOK_SECRET` are generated by Render. Keep both private.

## Connect the GitHub webhook

After the first successful deploy:

1. In Render, open `collabspace-app` → **Environment** and copy the generated `GITHUB_WEBHOOK_SECRET`.
2. In the GitHub repository, open **Settings → Webhooks → Add webhook**.
3. Set **Payload URL** to `https://<collabspace-app-host>/integrations/github` and **Content type** to `application/json`.
4. Paste the Render secret into **Secret**. Choose the push, pull request, pull request reviews, check runs, workflow runs, issues, and deployment status events; keep the webhook active and SSL verification enabled.
5. Save the webhook and confirm GitHub shows a successful recent delivery. The separate Render worker consumes queued events.

## Operations

- The app health check is `/health/ready`; it verifies PostgreSQL connectivity.
- PostgreSQL and Key Value use private network connection strings. Key Value has persistence enabled and `noeviction` for queue safety.
- The optional email notification worker is not included because SMTP credentials are not configured. Workspace invitation links remain available through the app's existing invitation flow.
- Configure a custom domain in Render only after the default URL is working; the self-referenced app URL updates through the Blueprint.
- Before inviting real users, verify registration, login, task/project CRUD, invitation acceptance, GitHub webhook deliveries, and a redeploy with the existing data intact.
